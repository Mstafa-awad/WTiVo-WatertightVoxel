# Troubleshooting

## `PyTorch cannot see an NVIDIA CUDA GPU`

Update/install the NVIDIA driver. WTiVo v1.0 has no CPU/AMD/Intel graph-solver fallback.

## `nvcc.exe was not found`

Install NVIDIA CUDA Toolkit 12.8. The CUDA runtime inside a PyTorch wheel is not the same thing as the development toolkit required to compile WTiVo's custom CUDA extension.

## CUDA says the MSVC compiler is unsupported

WTiVo setup prefers Visual Studio 2022 MSVC 14.38 / cl 19.38 because it is a known-good toolset and remains within CUDA 12.8's documented VS2022/MSVC 193x support. Open Visual Studio Installer and add **MSVC v143 - VS 2022 C++ x64/x86 build tools (v14.38-17.8)** if setup could not install it automatically.

`--allow-unsupported-msvc` exists only as an advanced escape hatch and adds NVIDIA's `-allow-unsupported-compiler`; it is not the recommended release configuration.

## vcpkg takes a long time

The first run compiles large C++ dependencies such as CGAL and OpenVDB. Subsequent setup runs reuse `.deps/vcpkg`.

## Import error for `wtivo_core`, `wtivo_vdb`, or `wtivo_gpupr`

Run `Setup-Windows.cmd` again, then run:

```bat
.venv\Scripts\python.exe scripts\verify_install.py
```

Do not copy `.pyd` files from a different Python/PyTorch/CUDA machine and expect them to be portable.

## Out of VRAM at 1536

Try:

```bat
Run-WTiVo.cmd --input "model.glb" --output "out.glb" --input-res 1024 --final-res 1024 --lambda_fill 10
```

Close other GPU-heavy applications. WTiVo's production benchmark used an ~8 GB GPU; 1536 is not guaranteed on smaller GPUs.

## System becomes slow / disk usage rises

Windows may page when system RAM is tight. The production path avoids explicitly emptying the process working set, but OpenVDB, CGAL topology, and large final meshes can still consume substantial RAM. Use a lower resolution and close large applications.

## `watertight=False`

Save the full console log and report the final `bad_edge_groups`, input/final resolutions, GPU model, PyTorch/CUDA versions, and input format. Do not hide the final checker: it is part of the production contract.

## Redistributing a built copy

If you bundle WTiVo with dependency DLLs/wheels, keep `build/installed-licenses/` generated by setup. It records the exact license/NOTICE files from the installed vcpkg/Python dependency set.
